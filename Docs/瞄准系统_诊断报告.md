### 2.1 对象清单

| 对象 | 位置 | 说明 |
|---|---|---|
| `Aim Target` | `firefly.prefab`（预制体实例中 = `CameraManager.aimTargetTransform`） | 瞄准目标点，唯一由脚本每帧写入的 Transform |

| `Two Hand Rig` | 模型根子物体，挂 `Rig`（weight 1） | 三个约束的容器 |
| `Hand Aim` | `Two Hand Rig` 第 2 个子物体，`MultiAimConstraint` | **唯一**的 aim 约束 |

| `WeaponAimingState` | `Assets/Scripts/Player/FSM/States/Weapon/WeaponAimingState.cs` | 进出瞄准状态、俯仰、开火 |

### 2.2 每帧数据流

```
鼠标 lookInput
  └─ WeaponAimingState.OnFixedUpdate
        aimPitch -= delta.y;  clamp(-10, +30)
        ctx.aimPivot(Follow).localRotation = Quaternion.Euler(aimPitch, 0, 0)
              │
              ├─► Cinemachine3rdPersonFollow 直接采用 Follow 的旋转（vcam 的 LookAt 被忽略）
              │        └─► Camera.main 的位置/朝向
              │                 └─► AimTargetUpdater.LateUpdate：射线 → Aim Target.position
              │                          ├─► Hand Aim (MultiAimConstraint) 让右手骨指向它
              │                          └─► WeaponAimingState.Fire() 用它算子弹方向
              └─► 身体骨骼：无任何消费者
```

### 2.3 关键数值（已核对）

| 项 | 值 | 出处 |

## 三、问题 1：只有手和枪低头，躯干不跟

### 3.1 现象
瞄准时右手和武器方向正确，但从瞄准相机看过去，人物上半身没有"跟着压下来"的姿态，和一般 TPS/FPS 的观感差距明显。

### 3.2 根因（三条叠加）

1. **rig 里只有一个 aim 约束，且只作用于右手骨骼**——脊柱、胸、颈、头没有任何约束。
2. **`ctx.aimPivot`（`Follow`）的俯仰只被相机消费**：`Cinemachine3rdPersonFollow` 把相机朝向设成 `Follow` 的旋转，但**身体没有任何一处读它**。所以俯仰表现为"相机 + 手"变化，躯干完全静止。
3. **动画层只切静态水平姿势**：`Arms.mask` 里 Body/Head 都是关的，`Aiming` 状态只播一个水平 aim clip；Base 层的 `Locomtion_Aim / Crouching_Aim` 也是水平姿势，全项目**没有俯仰变体 clip**。

### 3.3 修改思路（推荐：分布式 aim 链）

在 rig 里给脊柱/胸各加一节 `MultiAimConstraint`，指向同一个 `Aim Target`，但**只叠加一部分旋转**：

- 依据：job 内部是 `Quaternion.Lerp(drivenLRot, newRot, weight)` → **weight 就是"这块骨骼叠加多少 aim 旋转"**，所以降权重天然就是"分摊"。
- 三段叠加后，30° 的俯角能得到整体躯干前倾约 25°~35° 的效果，正好是主流 TPS 的压枪姿态。
- 不动动画、不动相机、不动现有手部约束，是三个方案里风险最低的（另两个方案：改 mask + 做新 clip 会与 Override 层冲突且需要新美术内容；代码里加性旋转骨骼会绕过 rig 形成第二套机制）。

### 3.4 具体步骤

**A. prefab 结构**（`Assets/Resources/Model/Player/Prefab/firefly.prefab`）

在 `Two Hand Rig` 下新增两个空 GameObject + `MultiAimConstraint`，**并拖到子物体列表最前面**（求值顺序 = 层级顺序，原因见 §5.1）：

| 顺序 | 新 GameObject | `m_ConstrainedObject` | `m_Weight` 初值 | 瞄准时权重 |
|---|---|---|---|---|
| 0 | `Spine Aim` | `上半身` (Spine) | 0 | 0.15 ~ 0.20 |
| 1 | `Chest Aim` | `上半身1` (Chest) | 0 | 0.30 ~ 0.35 |
| （保持不动） | `right hand constraint` / `Hand Aim` / `left hand constraint` | | | |

每个约束的字段（其余保持默认）：

- `m_SourceObjects[0]` = `Aim Target`，weight 1
- `m_AimAxis` = **Y (2)** 起手（必须按 §3.5 校准）
- `m_UpAxis` = Z_NEG (5)；`m_WorldUpType` = None
- `m_MinLimit / m_MaxLimit` = −180 / 180（**不要**在这里夹角度，夹取交给 §4）
- `m_Offset` = (0,0,0)、`m_MaintainOffset` = 0、`m_ConstrainedAxes` = (1,1,1)
- `m_Weight` = **0**（由脚本在瞄准时打开）

**B. 代码**（3 处，都很小）

1. `Assets/Scripts/Player/Data/PlayerFSMContext.cs`：与 `handAim` 并列新增两个 `MultiAimConstraint` 引用（`spineAim` / `chestAim`）。
2. prefab 的 `PlayerFSMContext` 上挂上这两个引用。
3. `WeaponAimingState`：
   - `OnEnter`：与 `ctx.handAim.weight = 1` 一起打开两节权重（建议用 `Mathf.MoveTowards` 做 0.15~0.25 s 淡入，避免瞬切）；
   - `OnExit`：归 0。

> **gate 不能省**：`Aim Target` 是常驻更新的（`AimTargetUpdater` 不判断是否在瞄准），只要 weight > 0 约束就恒生效，不 gate 的话跑步时身体也会朝准星方向偏。
> **只改 weight 不需要** `RigBuilder.Build()`（只有 target/binding 变化才需要重建，`WeaponController` 那种情况才调）。

### 3.5 轴校准流程（必做）

该 rig 的骨骼局部轴不是世界对齐的（例：`Head Pivot` 相对头骨骼的 localRotation 接近 180° 翻转），**不能靠猜**：

1. 进 Play → 按住右键瞄准 → 选中 `Spine Aim`；
2. 把 `m_Weight` 临时拉到 1，在 Scene 视图看躯干是否朝目标弯；
3. 方向不对（侧倒/后仰）就依次试 6 个 `m_AimAxis` 取值（X / X_NEG / Y / Y_NEG / Z / Z_NEG）；
4. 确认后把 weight 调回 0.15~0.20，再对 `Chest Aim` 重复一遍。

## 四、问题 2：贴脸时手往上甩

### 4.1 现象
目标距离很近（贴近敌人，命中距离 0.2~0.6 m）时，手会明显往上抬，角度超过 90°，不符合人体姿态。

### 4.2 根因（几何推导）

约束把手骨局部 +Y 转向 `(target − handPos)`，**而不是** `(target − camPos)`。相机和手不重合：

- 相机位置约在 pivot 后 0.82 m、高 1.47 m（由 ShoulderOffset / VerticalArmLength / CameraDistance 决定）；
- 右手在身前约 0.35 m；
- ⇒ 手到相机沿相机轴的分量 `v∥ ≈ −1.17 m`，横向/垂直偏移 `|v⊥| ≈ 0.15 ~ 0.3 m`。

设命中点到相机的距离为 `d`，手需要转过的角度：

```
θ(d) = atan2(|v⊥|, d + v∥)        （v∥ 为负，故 d 越小时分母越小甚至变号）
```

| 命中距离 d | 手需要转过的角度 θ |
|---|---|
| 0.3 m | ≈ 170°（方向整体翻到相机后方） |
| ≈ 1.17 m | 90° |
| 2.0 m | ≈ 10° |
| 5.0 m | ≈ 2° |

两个后果：
1. **命中距离小于"相机到手的沿轴距离"时**，手→目标向量翻到相机后方，手被要求转到 90° 以上甚至 170°——就是"贴脸往上甩"；
2. **接近 180° 时 `Vector3.Cross(fromDir, toDir)` 退化**，旋转轴逐帧乱翻 → 观感上还会抽搐。

> 关键结论：根因**不是"从哪个点出发"**，而是"目标点离相机太近"。所以"改成从枪口/肩膀出发"（常见方案 b）**不解决问题**——方向仍由同一个过近的命中点决定。

### 4.3 修改思路（最小瞄准距离夹取）

把目标点**沿相机射线推远到不小于 `minAimDistance`**，让它始终留在准星射线上、且不再落到手后面。

**文件：`Assets/Scripts/Camera/AimTargetUpdater.cs`（只需改 `LateUpdate`）**

```csharp
[SerializeField] private float minAimDistance = 2.5f;   // 建议 2.0 ~ 3.0

void LateUpdate()
{
    Ray ray = new Ray(aimCamera.transform.position, aimCamera.transform.forward);
    bool hit = Physics.Raycast(ray, out RaycastHit hitInfo, maxDistance, aimLayerMask);

    float distance = hit ? hitInfo.distance : maxDistance;
    distance = Mathf.Max(distance, minAimDistance);      // 关键：夹最小距离

    aimTarget.position = aimCamera.transform.position + aimCamera.transform.forward * distance;
}
```

- **为什么取 2.5 m**：按 §4.2 的几何，`d' = 2.0 → 10°`、`2.5 → 5.7°`、`3.0 → 4.6°`。而瞄准相机的距离是恒定值（`CameraZoomController` 只作用于 Normal Camera 的 FramingTransposer），所以这个阈值稳定、不会随缩放漂移。
- **连续性**：`Mathf.Max` 在阈值处 C0 连续，不会 pop；真正的跳变只来自"射线换了命中面"，那是原本就有的行为。
- **命中与未命中都过一遍**，两个分支合并后逻辑更统一。

### 4.4 连带影响与取舍

| 影响 | 说明 |
|---|---|
| 子弹方向 | `Fire()` 用的就是同一个 `Aim Target`，所以**自动跟着改**，不需要动 `Fire()`；好处是贴脸时枪口不再需要"拧 170°" |
| 弹着点偏差 | 枪口与相机有约 0.13 m 横向视差，`2.5 m` 处对应约 **3°** 偏角，属正常"枪口-相机视差" |
| 贴脸精度 | 命中距离 < `minAimDistance` 时枪口不再精确指向命中点，极窄目标可能擦过。若要"贴脸必中"，需要给子弹单独存一份未夹取的命中点（本次不做） |
| 可选保险 | 把 `Hand Aim` 的限位从 ±180 收到 ±70~80。注意限位的参照系是**当前动画姿势的 aim 方向**（不是相机前方），俯角 30° 时动画姿势仍是水平的，余量会被吃掉——所以它只能当保险，不能当主修 |

## 五、附带发现（低风险，可顺手清理）

1. **`WeaponAimingState.GetAimTargetPosition()` 的射线没有 LayerMask**（`Physics.Raycast(ray, out hit, 100f)`），默认会命中除 Ignore Raycast 外的所有层，**包含玩家自己的 layer 6**；而 Normal Camera 在 3 m 外朝 1.65 m 高的 pivot 看，这条射线很可能先打中自己 → `AlignPlayerToTarget` 用"自己背上"的方向算水平朝向与俯仰 → 入瞄准瞬间人物朝向/俯仰抖一下。
   建议：`OnEnter` 直接改用 `CameraManager.Instance.AimTargetTransform.position`（已经是"带 mask + 会夹取 + 与准星一致"的点），把这个方法删掉。顺带消掉 fallback 不一致（`AimTargetUpdater` 未命中推 100 m，这里推 50 m）。
2. **`ctx.headPivot`（`Head Pivot`）全工程只有一处被注释掉的引用**；`AimPivolt`（未激活）也无任何引用。
   ⚠️ 不要把它们当 `MultiAimConstraint` 的 source：它们都是**骨骼的子物体**，属于自引用（和 `Right Hand Aim Target` 同一个病），会产生逐帧漂移。要做头部跟随，直接把头骨骼挂到 `m_ConstrainedObject`。
3. **俯仰范围是 −10 ~ +30**：向下的余量只有 10°，贴脸低头时往往已经到 clamp 上限，玩家无法真正"低头看脚下"，此时手只能靠 MultiAim 硬追——会**加剧**问题 2 的观感。修完问题 2 后如果仍觉得别扭，可以把这个下限放宽（如 −35）。
4. **求值时序**：Animator/rig 在动画阶段求值（Update 之后、LateUpdate 之前），相机在 LateUpdate 由 CinemachineBrain 写 → 射线用的是上一帧末的相机位姿，而 rig 消费的是上一帧写入的目标点，两侧各差 1 帧（快速甩鼠标时手比准星慢约 5°）。
   判定：**不是这两个问题的原因，不建议为此重构**（rig 搬不进 LateUpdate）。可选卫生项：把 `AimTargetUpdater` 的执行顺序设到 CinemachineBrain 之后，保证射线用当帧最新位姿。
5. **`ctx.canRun` 是死代码**：`WeaponAimingState` 里 `ctx.canRun = false/true` 全工程无人读取，瞄准并没有真的禁跑（`runSpeedActual` 也没被瞄准修改）。与本次两个问题无关，仅记录。

## 六、保护清单（不要动）

| # | 不要动 | 原因 |
|---|---|---|
| 1 | `Two Hand Rig` 现有三个约束的**顺序** | `right hand constraint` 的 `m_TargetRotationWeight: 1` 且 target 是手自己的子物体，会给手叠一个约 60° 的常量旋转；一旦它被排到 `Hand Aim` 之后，枪会立刻指歪。新增的 Body 约束**只能插在最前面** |
| 2 | `Right Hand Aim Target` 的自引用设计 | 靠 position 解算给手约 9 cm 偏置，`Handle` 与武器的对齐就是按它调好的 |
| 3 | `Handle` 的 `localRotation`（≈ (0.7071, −0.7071, 0, 0)） | 这是"手 +Y ↔ 枪口方向"的映射常量，动它等于重新校准武器 |
| 4 | `Aim Target` 下的 `Cuberrwe` | 它带 BoxCollider，启用会在命中点生成物理碰撞体、可能干扰子弹。调试请用 `Debug.DrawRay` |
| 5 | `Arms.mask` 与 Arms 层权重 | 该层是 **Override、权重 1**；把 Body/Head 加进 mask 会让 Base 层的 aim locomotion 上半身被静态姿势覆盖（走起来僵住） |
| 6 | `Cinemachine3rdPersonFollow` 的参数 | §4.3 的 `minAimDistance` 是按这些值反推的，改了要重算 |
| 7 | 不要旋转 player root | CharacterController 胶囊会跟着倒、脚会离地 |
| 8 | 不要旋转模型根 | `Follow` 是它的子物体 → 相机双倍俯仰，需要反算补偿 |
| 9 | `AlignPlayerToTarget` 的入瞄准对齐 | 这是刻意的设计；只替换"取点来源"，别删掉对齐本身 |

## 八、Unity API 表

### 8.1 问题 2（`AimTargetUpdater`）

| API | 作用 | 备注 |
|---|---|---|
| `Camera.main` | 取带 CinemachineBrain 的主相机 | 现有代码已在用 |
| `Camera.transform.position` / `.forward` | 射线起点 / 方向 | 现有代码已在用 |
| `Physics.Raycast(Ray, out RaycastHit, float, int)` | 瞄准射线 | 现有代码已在用 |
| `RaycastHit.point` | 原始命中点 | 现有；改为不再直接用 |
| **`RaycastHit.distance`** | 命中距离 | **新增读取**，夹取依据 |
| **`Mathf.Max(float, float)`** | 最小距离夹取 | **本次核心** |
| `Vector3` 运算符 / `Vector3.normalized` | 沿射线重算目标点 | 现有 |
| `Transform.position`（setter） | 写 `Aim Target` 世界坐标 | 现有 |
| `SerializeField` / `Header` / `Tooltip` | 暴露 `minAimDistance` 供 Inspector 调参 | 新增 |

### 8.2 问题 1（Animation Rigging）

| API | 作用 | 备注 |
|---|---|---|
| `UnityEngine.Animations.Rigging.MultiAimConstraint` | 新增的躯干瞄准约束 | 新增 2 个 |
